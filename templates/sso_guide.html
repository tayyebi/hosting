Integrate your app with Platform as an identity provider

Platform acts as an Identity Provider (IdP). Your app is the Relying Party (RP) or Service Provider (SP). Users authenticate once with Platform; your app receives a verified identity token.

1
Register your application
Get a Client ID and Secret from the SSO → Clients panel
  1. Go to Sysadmin → SSO → Clients and click Register client.
  2. Enter your application name and choose a protocol.
  3. Add one or more redirect URIs — must exactly match what your app sends.
  4. Copy the Client ID and Client Secret. The secret is shown once.
Never expose your Client Secret in frontend code or public repositories. Store it in environment variables or a secrets manager.

Redirect URI rules

  • Exact string match — no wildcards.
  • http://localhost is allowed for local development only.
  • Production URIs must use https://.
  • Up to 10 redirect URIs per client.
2
OAuth 2.0
Authorization Code flow — the recommended approach for server-side apps
Authorize/sso/oauth2/authorize
Token/sso/oauth2/token
Revoke/sso/oauth2/revoke

Step 1 — Redirect the user

HTTP
GET /sso/oauth2/authorize
  ?response_type=code
  &client_id=YOUR_CLIENT_ID
  &redirect_uri=https://yourapp.com/callback
  &scope=openid+email+profile
  &state=RANDOM_CSRF_TOKEN

Step 2 — Exchange the code

HTTP
POST /sso/oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code=AUTH_CODE
&redirect_uri=https://yourapp.com/callback
&client_id=YOUR_CLIENT_ID
&client_secret=YOUR_CLIENT_SECRET

PKCE — for SPAs & mobile

Generate a code_verifier (43–128 random chars) and code_challenge = BASE64URL(SHA256(verifier)). Include both in the authorize request; send only the verifier in the token exchange.

HTTP
GET /sso/oauth2/authorize
  ?response_type=code
  &client_id=YOUR_CLIENT_ID
  &redirect_uri=https://yourapp.com/callback
  &scope=openid+email
  &state=RANDOM_STATE
  &code_challenge=BASE64URL_SHA256_OF_VERIFIER
  &code_challenge_method=S256

Available scopes

openidRequired for OIDC. Returns an ID token.
emailUser's email address.
profileDisplay name and avatar.
rolesPlatform roles assigned to the user.
tenantTenant identifier and metadata.
offline_accessIssues a refresh token.

ID Token payload

JWT payload
{
  "iss":   "https://platform.internal/sso",
  "sub":   "usr_4a9f2e8b",
  "aud":   "YOUR_CLIENT_ID",
  "exp":   1713000000,
  "iat":   1712996400,
  "email": "alice@example.com",
  "name":  "Alice Smith",
  "roles": ["tenant:admin"],
  "tid":   "tenant_xyz"
}

Validation checklist

  1. Fetch the public key from /sso/.well-known/jwks.json matching the kid header.
  2. Verify the signature using RS256.
  3. Check iss equals https://platform.internal/sso.
  4. Check aud contains your Client ID.
  5. Check exp has not passed.

Library quick-start

JS
import { Issuer } from 'openid-client';

const issuer = await Issuer.discover(
  'https://platform.internal/sso'
);
const client = new issuer.Client({
  client_id:      'YOUR_CLIENT_ID',
  client_secret:  'YOUR_CLIENT_SECRET',
  redirect_uris:  ['https://yourapp.com/callback'],
  response_types: ['code'],
});
Python
from authlib.integrations.requests_client import OAuth2Session

client = OAuth2Session(
    client_id='YOUR_CLIENT_ID',
    client_secret='YOUR_CLIENT_SECRET',
    scope='openid email profile',
    redirect_uri='https://yourapp.com/callback',

uri, state = client.create_authorization_url(
    'https://platform.internal/sso/oauth2/authorize'
)

SP setup checklist

  1. Download the IdP metadata from /sso/saml/metadata and import it into your SP.
  2. Provide your SP metadata (Entity ID + ACS URL) to a sysadmin for registration.
  3. Ensure your SP trusts assertions signed with RSA-SHA256.
  4. Set NameID format to emailAddress.

Assertion attributes

NameIDUser's email address.
displayNameFull name of the user.
rolesComma-separated platform roles.
tenantIdTenant identifier string.
Always validate InResponseTo to prevent replay attacks. Check NotOnOrAfter and NotBefore before accepting any assertion.
5
Token management
Refresh, revoke, and understand token lifetimes

Refresh an access token

HTTP
POST /sso/oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=refresh_token
&refresh_token=REFRESH_TOKEN
&client_id=YOUR_CLIENT_ID
&client_secret=YOUR_CLIENT_SECRET

Revoke a token

HTTP
POST /sso/oauth2/revoke
Content-Type: application/x-www-form-urlencoded

token=TOKEN_TO_REVOKE
&token_type_hint=refresh_token
&client_id=YOUR_CLIENT_ID
&client_secret=YOUR_CLIENT_SECRET

Token lifetimes

Access token1 hour (configurable)
Refresh token30 days (configurable)
ID token1 hour
Auth code5 minutes — one-time use

unauthorized_clientGrant type not enabled.
access_deniedUser denied the request.

API Rate Limits
Per-client request limits enforced across all SSO endpoints
Endpoint Limit Window
/oauth/token 100 requests 1 minute
/oauth/authorize 200 requests 1 minute
/userinfo 300 requests 1 minute
/oauth/revoke 50 requests 1 minute
/.well-known/* 600 requests 1 minute
/saml/sso 150 requests 1 minute
Exceeding rate limits returns 429 Too Many Requests with a Retry-After header. Implement exponential back-off in production clients.
